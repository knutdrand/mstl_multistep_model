# Debug fixture — one champion test split

Generated by `scripts/make_debug_split.py` (champion `config_tgtlag3_var`). A small,
inspectable slice for debugging the data flow into the Random Forest residual model.

- **Sectors:** 5 full-history locations (biased to include sprayed ones so IRS features fire).
- **Split:** one held-out window — train `2013-01 .. 2025-10`, forecast `2025-11, 2025-12, 2026-01`
  (the most recent 3 months; `n_periods=3`, the harness's first split).

## Files

| file | rows | what it is |
|---|---|---|
| `raw_historic.csv` | 770 | raw CHAP rows the model is **fit** on (full 20-column schema) |
| `raw_future.csv` | 15 | raw CHAP rows to **forecast** (target `disease_cases` is the held-out truth) |
| `rf_train_design.csv` | 770 | the design the RF is **trained** on (see below) |
| `rf_predict_design.csv` | 15 | the future feature rows fed to `rf.predict()` at forecast time |

## `rf_train_design.csv`

One row per (`time_period`, `location`). Columns: the two index columns, then the **24 RF
feature columns**, then the target and a mask:

- **Climate anomaly lags (12):** `rainfall_era5_lag1..6`, `mean_temperature_lag1..2`,
  `relative_humidity_lag1..4` — each climate covariate is MSTL-deseasonalised first (so these
  are anomalies and can be negative) then lagged with its per-covariate window.
- **Location one-hot (5):** `loc_<id>`.
- **IRS features (4):** `irs_level`, `irs_decay`, `irs_since`, `irs_cumulative` (dense,
  contemporaneous, from the sparse `irs_allocated` column).
- **Target lags (3):** `tgt_lag1..3` — the deseasonalised target `D` lagged 1–3 months.
- **`_resid`** — the RF **target**: the ARIMA residual `R = D - Â` (deseasonalised log-target
  minus the ARIMA in-sample fit).
- **`in_mask`** — `True` for the rows the RF actually trains on; `False` rows are dropped
  because a lag or `_resid` is NaN (early history). 705 train rows, 65 dropped.

The RF is trained on `X = rf_train_design[feature_cols][in_mask]`, `y = _resid[in_mask]`.

## `rf_predict_design.csv`

The `Xf` matrix fed to `rf.predict()` for the 3 forecast steps of each sector. Same feature
columns. Note the **target-lag bridge**: future `tgt_lag*` values that fall ahead of the
forecast origin are filled with the ARIMA mean forecast (non-recursive bridge), not future truth.

## Plots (`debug/plots/`)

Generated by `scripts/plot_debug_design.py` from `rf_train_design.csv`:

- `design_resid.png` — the RF target `R` per sector over time; grey bands mark rows dropped
  by the lag/NaN mask (early lag warm-up + any mid-series data gaps).
- `design_feature_corr.png` — correlation of each feature with `R` (on in-mask rows), coloured
  by block. Correlations are weak (max ~0.10: `irs_decay`, `irs_since`, target lags) — expected,
  since `R` is precisely what ARIMA could *not* explain.
- `design_features_sector.png` — feature-construction sanity for one sprayed sector: `R`, a
  rainfall lag, the IRS features (level spikes / geometric decay / months-since), and the
  target lags over time.

## Fidelity

`make_debug_split.py` asserts the labeled reconstruction equals, bit-for-bit, the arrays the
model actually hands to the RF during `fit()` and `predict()` — so these CSVs are exactly what
the model sees, not an approximation. Regenerate with `uv run python scripts/make_debug_split.py`.
